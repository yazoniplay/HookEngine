HookEngine · Privacy

Privacy Policy

Last updated: November 1, 2026

This policy explains what HookEngine processes when you use its browser extension, generation service and account portal. It describes the data flows implemented in the current code and database migrations.

Information associated with your account

  • Account details: Your email address and authentication credentials are handled through Supabase Auth.
  • Generation records: Generated drafts are stored in your HookEngine database and shown in your account history, alongside related generation records. Records can include the source title and URL, source type, selected platforms, generation status, provider and model names, token counts, timing, credit usage, estimated provider cost, timestamps and an error message when a generation fails.
  • Source fingerprint: The generation reservation function calculates a SHA-256 hash and character length for submitted source text. It stores those values instead of the raw source text in the generation record.

How source material is processed

When you request text generation, the source text, source title, writing preferences and requested platform instructions are sent from the HookEngine service to the AI provider handling that request. For YouTube video analysis, the video URL and generation instructions are sent to Google Gemini.

Raw source text is not retained in HookEngine's generation records. The reservation function stores a null value in the source-text column and records the SHA-256 hash and character length. This statement concerns HookEngine's database; it does not make a claim about temporary processing or the separate data practices of AI providers.

AI and infrastructure providers

  • Google Gemini: Primary text-generation provider and the provider used for YouTube video analysis.
  • Groq and Ollama Cloud: Configurable fallback providers for text generation when enabled in the service configuration.
  • Supabase: Provides authentication and the database used for account and generation records.

The content needed to complete a request is sent to the provider that processes it. Each provider handles requests under its own terms and privacy practices; review those provider policies if you need details about their processing or retention.

How long information remains available

  • Free history: The database makes Free-plan generation history visible for the configured Free-plan window.
  • Paid history: Pro and Lifetime plans have no age-based history cutoff in the database. Paid history remains associated with the account until account deletion; there is no separate automatic draft-expiry period defined by the history policy.
  • Source text: The current reservation function stores a hash and length rather than raw source text. A scheduled cleanup function also clears any legacy non-null source-text values it encounters.

The current account portal does not provide a self-service control for deleting individual history records or deleting an account. Generation records are linked to the authentication account with database cascade behavior when that account is deleted.

Access and security controls

Generation and account records are scoped to the authenticated account through database row-level security policies. The browser account portal reads the signed-in user's own generation history and usage data.

Changes to this policy

This page may be updated when the product's data flows or database behavior changes. The “Last updated” date will be revised when the policy is changed.
